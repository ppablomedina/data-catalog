rent /  Rental 
  • https://api.nextbike.net/api/rent.xml?apikey=REDACTED&loginkey=REDACTED&bike=12345
  • Callback events: These states represent a typical life cycle of a rental
Callback eventDescription
rent bike has been rented (though makes no sense, if you trigger "rent", but could be used for strictly event-based architectures or if a booking turns into a rental)  
unlock the lock has been opened (only available for specific bike types) 
pause_start the rental is in "pause" / "break" state, closing the lock will not return the bike 
lock the lock has been closed (only available for specific bike types) - could be during pause or to return the bike 
pause_end an active break has ended; if the rental is still running, the next closing of the lock will return the bike 
return bike returned has been registered successfully, but price calculation may not be completed yet 
service_case A "service case" has been triggered, e.g. additional fees for returning outside of flex zone, a free warning about this, a bonus for returning to an empty station 
complete Our typical price calculations are completed, we received a good GPS position and applied all service fees, if required 
price The price of the rental changed. This happen during return (if price > 0) or completed, but also if customer service invalidates a rental or adjusts its price later 
comment The "comments for customer" changed, e.g. including infos from customer service or feedback regarding the rental 
resume the same bike has been rented again by the same customer, without another customer renting it in between and it would be cheaper for the customer to have one continuous rental instead of two separate. (E.g. after service fee for return outside of flex zone has been applied and customer wants to bring it back to an official station). Rental ID remains the same, time between original return and resume will be converted into a rental pause / break. All paid fees will be credited to the customer account and a new price calculation will take place with next return. You may turn of resume by setting "no_resume" (though it could be resumed through another channel) 
overtime The rental takes longer than typical rentals (feature is enabled for a few brands, "typical" rental duration set by brands). Can trigger multiple times (e.g. after 2, 12, 24, 36, 48 hours) 
distance The distance of the rental has been calculated (happen 15mns after the bike has been returned) 
  • Most integrators are happy with the "return" callback to indicate a successful return and "complete" + consecutive "price" to trigger the factoring and debt purchase.
  • The "resume" event is the trickiest, because it uses the same rental ID and may shake up already factored rentals. You can disable the feature in your integration, by setting "no_resume", but customer may hate you for this.

rentalBreak /  Parking 
  • User can park the bike by making rentalBreak
  • Start parking without parameter 'end'
  • Start example: https://api.nextbike.net/api/rentalBreak.xml?apikey=REDACTED&loginkey=REDACTED&rental=123456&lat=52.323001&lng=43.212223
  • Response includes the rental node with the attribute "break"
  • If "break" is true, then the rental is in pause mode
  • User have to close the lock manually (starts a return request)
  • API cancels the return process because the rental is in break
  • Starting a break sends pause_start before the lock is closed
  • Closing the lock during a break sends lock and does not return the bike
  • Opening the lock or ending the break sends pause_end
  • Returning a bike during a break ends the break and sends pause_end and return
  • End parking with parameter 'end'
  • End example: https://api.nextbike.net/api/rentalBreak.xml?apikey=REDACTED&loginkey=REDACTED&rental=123456&end=1
  • Response parameter "break" will be false
  • If the customer already returned the bike, starting a new rentalBreak is the same like rent with start_paused=1&resume=1 (previous rental will be resumed and directly set to break mode)
